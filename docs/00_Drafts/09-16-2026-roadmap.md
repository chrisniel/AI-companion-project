## Voice roadmap specifically

Since this is probably the one you'll keep asking about now that you've downloaded half the speech stack like a responsible digital hoarder. 😂

The canonical voice architecture has **V0–V6**:

| Voice Track                 | Implementation                                                       |
| --------------------------- | -------------------------------------------------------------------- |
| **V0 Audio Foundation**     | Microphone/speaker device manager, PCM capture/playback, buffers     |
| **V1 Listening**            | **Silero VAD + Whisper STT**                                         |
| **V2 Speaking**             | **Kokoro TTS**, voice profiles, streaming synthesis                  |
| **V3 Conversational Voice** | Full listen → transcribe → think → speak loop, interruption/barge-in |
| **V4 Wake Word**            | openWakeWord or equivalent                                           |
| **V5 Android Remote Audio** | Phone mic/speaker streaming to PC runtime                            |
| **V6 Advanced Voice**       | Speaker recognition, denoise, emotion/prosody, advanced processing   |

So the things you've already downloaded map neatly to:

```text
whisper.cpp runtime  → Voice V1
Whisper model        → Voice V1

silero_vad.onnx      → Voice V1

kokoro.onnx          → Voice V2
Kokoro voices        → Voice V2
```

We're **not implementing them yet**, but 8P.3 is preparing their permanent storage locations so we don't later have to move the entire nervous system because someone stored Kokoro beside `llama-server.exe`.

## Character/Profile roadmap

Our locked ownership model is:

```text
Local User Profile
├── conversations
├── memories
├── tasks
├── preferences
└── preferred character

Character
├── identity
├── system/persona prompt
├── personality traits
├── preferred voice
└── presence configuration

Voice
└── how the character sounds

Presence
└── how the character appears
```

The crucial rule is:

> **Profile owns user data. Character never owns conversations, memories, or tasks.**

And:

> **Character decides WHO/HOW. Voice decides HOW IT SOUNDS. Presence decides HOW IT APPEARS. Profile owns USER DATA.**

That prevents switching from Lisa to some future character from somehow deleting your memories, which would be a rather dramatic character-selection feature.

## Android comes after the backend foundations

The Android UI already exists quite far ahead visually, but a lot of its repositories are still fake/in-memory. The master plan describes the next major Android direction as replacing those with real Local AI Runtime integration through REST/event streams, while on-device failover remains a later capability.

So don't confuse:

```text
Android UI exists ✅

Android fully integrated with backend ❌ later

Android runs its own local LLM ❌ much later
```

The future edge architecture is roughly:

```text
PC available
    ↓
Android → PC Local AI Runtime → full LLM/memory/tools

PC unavailable
    ↓
Android → small local edge model
         limited context/features
```
