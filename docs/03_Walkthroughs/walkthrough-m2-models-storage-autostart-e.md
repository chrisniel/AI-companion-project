## 3. How the Logic Works

1. **Five Storage Roots & Relocation:** `get_canonical_paths()` derives `APP_INSTALL_ROOT`, `DATA_ROOT`, `LIBRARY_ROOT`, `CACHE_ROOT`, and `LOG_ROOT` purely from env overrides and `bootstrap.json` (ignoring global `bootstrap.json` `library_root` when `COMPANION_DATA_ROOT` env isolates a test run). `PUT /api/v1/system/storage/library-root` stops any idle router, verifies path safety, copies/verifies assets when requested, atomically updates `bootstrap.json`, emits `storageRevision` updates in Flutter so Runtime clears stale scans and updates its inbox path, and returns updated `StorageRootsResponse`.
2. **D6 Controlled Model Import, Dynamic Hardware Probe, Smart CTX & Vision/Reasoning Pairing:** User picks files directly via native Win32 **Add Model Files...** (`WindowsShellChannel` + Copy/Move staging) or drops `.gguf` (+ optional `mmproj-*.gguf`) into the auto-created `IMPORT_INBOX_DIR` (`<LIBRARY_ROOT>/imports/inbox`) and clicks **Scan Inbox** (`POST /models/import/scan`). `scan_import_inbox()` surfaces safety/engine warnings (blocking `.pt`/`.pth`/`.pkl`/`.ckpt`, explaining skipped `.safetensors`/`.onnx`/`.bin`), inspects GGUF headers (buffered `_skip_gguf_array`, bounded `tokenizer.chat_template`, `_GGUF_METADATA_CACHE`) to detect `reasoning_mode` (`toggleable`/`always_on`/`unsupported`) and vision projector metadata (`embedding_length`, `clip.projector_type`, `clip.vision.projection_dim`, `general.basename`, `general.tags`), scores compatible projectors via `score_mmproj_compatibility()` + `is_vision_capable_primary()` without blind `[0]` fallback, and runs `assess_hardware_suitability()`, `compute_recommended_profiles_for_model()`, and `assess_context_options()` against `probe_host_hardware()` Win32 GPU VRAM & RAM. On **Install Bundle** (`POST /models/import/install`), files stage into a unique `IMPORT_STAGING_DIR` subdir, enforce compatible `companion_relative_path` (HTTP 400 on mismatch), verify SHA-256 + GGUF validity, move atomically (`os.replace`) into `<MODEL_LIBRARY_DIR>/<model_id>/` (respecting `transfer_mode`: `"move"` or `"copy"`), persist Schema v3 `models.json` (including `reasoning_mode`, `"reasoning"` capability, & `recommended_profiles`), and promote idle `MockLLMProvider` in `auto` mode. Unified `context_mode` (`"profile"`, `"2k"`, `"4k"`, `"8k"`, `"16k"`, `"32k"`, `"model_max"`) persists in `host_config.json`, disables VRAM-overflow / `exceeds_model_max` choices in the UI by default unless opt-in **Allow unsafe experimental CTX** unlocks overflow options (`exceeds_model_max` remains strictly blocked), offers a **Reset to Auto (Profile Default)** warning banner, and resets active Core-managed router state cleanly on change.
3. **Windows Login Autostart, Cold-Boot Supervision Resilience & Flash-Free Tray / Maximized Startup Launch:** Toggling **Launch at Windows Login** (`PUT /system/autostart`) builds UTF-16LE BOM-encoded (`<?xml version="1.0" encoding="UTF-16"?>`, `encoding="utf-16"`) Task Scheduler XML (`AICompanionAutostart`, `<UserId>` followed by `<Delay>PT5S</Delay>` inside `<LogonTrigger>`, `<Principal id="Author">`, `LeastPrivilege`, `<Priority>5</Priority>`, explicit `WorkingDirectory`, `--minimized-to-tray`, with encoding normalization on `get_status()`) via `WindowsAutostartService`, with `CompanionClient._handleErrorResponse()` unwrapping nested `body['error']['message']`/`['code']` payloads. On Windows launch, `main.cpp` forwards `--minimized-to-tray` -> `FlutterWindow` skips first-frame show -> `main.dart` awaits `DesktopLifecycleCoordinator.initialize(showImmediately: ..., maximizeOnStart: ...)` which keeps `--minimized-to-tray` hidden until first `restoreAndFocusWindow()` maximizes it once and triggers `onWindowRestored` auto-retry if local runtime is still offline, while normal launches maximize immediately and `SetNextFrameCallback` preserves `SW_SHOWMAXIMIZED` (instead of calling `Win32Window::Show()` `SW_SHOWNORMAL`). `AiCompanionDesktopApp` grants `--minimized-to-tray` autostart launches a `60s` startup timeout while `WindowsRuntimeProcessSupervisor.discoverRuntimeProcesses()` (`12s` default timeout) and `DesktopRuntimeCoordinator` (retrying transient timeout-only `inspectionUnavailable` failures up to `3` attempts without weakening fail-closed access/error checks) absorb slow post-boot WMI/CIM readiness, `DesktopRuntimeCoordinator` resolves the backend executable up to `10` ancestor directories deep, and `SettingsRuntimeSection` exposes `Diagnostic Detail` + 1-click **Start Local Runtime** / **Start / Retry Local Runtime** (`30s` **Apply & Save** timeout).

## 4. Key Concepts

- **`LIBRARY_ROOT` Isolation & Same-Volume Staging:** Placing `imports/inbox` and `imports/staging` inside `LIBRARY_ROOT` keeps large GGUF staging atomic (`os.replace`) even when `LIBRARY_ROOT` moves to `D:\` or `E:\`.
- **Dynamic Host Hardware Preflight & Safe Smart Context Guardrails:** `assess_hardware_suitability()`, `compute_recommended_profiles_for_model()`, and `assess_context_options()` calibrate profile and context-window options (`profile` / `2k` / `4k` / `8k` / `16k` / `32k` / `model_max`) against probed PC VRAM/RAM and model header maximums, disabling unsafe choices by default behind opt-in **Allow unsafe experimental CTX** while keeping `exceeds_model_max` strictly blocked.
- **No Watchdog `/RI` Autostart:** Registering `LogonTrigger` cleanly without periodic restart intervals ensures `Exit Companion` stops the app intentionally as required by D2.

## 7. Troubleshooting

- **Symptom:** Async chat streaming tests timed out (`2.0s`) during `build_model_list()`.
  - **Likely cause:** Calling `f.seek()` on every small string element in `tokenizer.ggml.tokens`/`merges` flushed Python's `BufferedReader` ~300k times per `.gguf` file.
  - **Resolution:** Sequential buffered reads (`<= 65536` bytes) in `_skip_gguf_array()` + size/mtime `_GGUF_METADATA_CACHE` (`>= 64 KB`) in `model_registry.py` cut `build_model_list()` latency from `2.803s` down to fast cached lookups and restored `test_attachment_binding.py` + `test_model_registry.py` to `84 passed in 18.63s`.
