## 3. How the Logic Works

1. **Native WASAPI & Hotkey Bridge:** `FlutterWindow` owns `WindowsAudioChannel`, registering `ai_companion/windows_audio` and routing `kWmAudioEvent` + `WM_HOTKEY` window messages safely on the UI STA thread while dedicated MTA audio threads capture 16 kHz PCM16 frames and mix/resample WAV/PCM output with generation-tagged buffer flushing. Tray right-click invokes `popUpContextMenu()` and preserves the mute check state across runtime heartbeats.
2. **Voice Control, Performance & Isolation:** `DesktopVoiceController` coordinates hardware endpoint selection, WASAPI mic hot-swap, Settings **Test Mic**, isolated 60 Hz `micRmsListenable` UI meters (zero root-shell rebuild thrash), root `HardwareKeyboard` shortcuts, hard mute (`setMuted` stops OS capture & syncs tray/shell/chat pills), single-shot Composer dictation, sentence-pipelined Read Aloud with playback-aware button reset, and live duplex `WS /api/v1/voice/ws` turns; Profile switches invoke `handleProfileEpochChanged` to tear down audio/WS state immediately.
3. **Backend Context Resilience & Real-Time Speech Synthesis:** Assistant orchestration compacts tool schemas, weights UTF-8 tokens, skips empty failed rows, and steps down auto-compaction cleanly inside 4,096 windows. `KokoroOnnxTtsProvider` normalizes text, resolves English IPA via `espeak-ng` and Tagalog words phonemically, chunks past 510 tokens, and streams segments from an ordered async queue fed by hands-free Silero VAD speech+silence turn endpointing.
